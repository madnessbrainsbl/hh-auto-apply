# HH Auto-Apply

Поиск вакансий, отклики через Selenium, AI-письма и ответы на анкеты, подъём резюме, локальная история и анализ отказов.

## Установка и запуск

Нужны Python 3.10+ и Google Chrome.

На Windows запустите `setup.bat` для установки зависимостей, затем `run_test.bat` для открытия меню. Либо запустите из PowerShell:

```powershell
python -m pip install -r requirements.txt
python test.py
```

В `menu.bat` и `menu.sh` пункт **N** открывает это меню. В Python-меню:

- **N → L** — войти в HH в видимом браузере, без отправки откликов.
- **P → R** — выбрать целевое резюме.
- **N → S** — направление поиска.
- **N → T** — письмо и контакты.
- **N → G / K** — основной Gemini / запасной Groq.
- **N → F** — AI-фильтрация и Vision для текстовой капчи.
- **N → U** — открыть или создать отдельный аккаунт.

Проверьте свои данные в `candidate_profile` в настройках выбранного аккаунта. AI-фильтр использует именно эти данные; он не предполагает, что вы владеете навыками из описания вакансии. Новый профиль создаётся с пустыми резюме, данными кандидата и ключами.

## API HH

Зарегистрировать приложение и получить реквизиты можно на [портале API HH](https://dev.hh.ru/). Для работы через API задайте `HH_CLIENT_ID` и `HH_CLIENT_SECRET` в окружении. Контактный email задаётся через `HH_CONTACT_EMAIL`.

## Собеседования

[Talkaside](https://app.talkaside.workers.dev/) — мой проект для собеседований.

## AI-фильтрация

По умолчанию выключена, чтобы добавление функции не меняло текущий отбор. Работает до создания письма и нажатия кнопки отклика, в обработке кеша и поиске на сайте. При включении полный цикл также направляет отправку через этот общий браузерный путь.

| Режим | Контекст |
|---|---|
| `off` | Без AI-фильтра |
| `light` | Название, навыки вакансии, специализация и навыки кандидата |
| `heavy` | Дополнительно описание вакансии и заполненные поля опыта, образования, условий и «О себе» кандидата |
| `custom` | Контекст heavy и критерии пользователя |

```powershell
python hh.py settings --ai-filter heavy
python hh.py settings --ai-filter custom --filter-prompt "Только удалённый Python backend"
python hh.py settings --ai-filter off
```

Фильтр использует существующую цепочку AI-провайдеров, включая настроенные CLI-провайдеры. При отсутствии ответа или неправильном JSON отклик не отправляется, вакансия остаётся для повторной проверки. Решение и причина сохраняются в SQLite: `ai_filter` — отклонение, `ai_unavailable` — отложенная проверка. Имя и контакты кандидата в запрос фильтра не включаются.

## Отбор вакансий и письма

### Память подтверждённых ответов на анкеты

После успешного заполнения простого вопроса бот сохраняет ответ как черновик в локальной
базе текущего аккаунта. Откройте **N → Q → M**, выберите запись и нажмите **C**, чтобы
подтвердить ответ для следующих вакансий, или **E**, чтобы сначала исправить его.
Для списка и переключателей указываются номера вариантов; для нескольких галочек — через запятую.
Клавиша **-** удаляет ответ и отключает повторное предложение этой записи.

Только подтверждение пользователем разрешает повторное использование: генерация ИИ,
заполнение поля и отправка отклика сами по себе подтверждением не считаются.
Подтверждённый ответ подставляется до обращения к ИИ, в том числе при выключенном ИИ.
Совпадать должны текст вопроса, тип поля и набор вариантов; порядок вариантов может меняться.
Поиск по похожему смыслу не используется, чтобы не перепутать отрицания и условия.
Память разделена по аккаунту, выбранному резюме и данным профиля. После изменения профиля,
настроенных ответов или политики ответов старые записи автоматически перестают подставляться.
Вопросы, зависящие от конкретного работодателя («почему хотите работать у нас»), согласия
на обработку персональных данных и вопросы
с ограничениями действующей политики, неоднозначные дубли и смешанные блоки со «своим вариантом»
в повторное использование не попадают. Содержимое памяти остаётся в локальной `hh_data.db`.

В направлении ИБ продажи и пресейл исключаются до принятия вакансии: `Presale`, `Pre-Sale`, `Sales Engineer`, `Account Manager/Executive`, `Business Development` и `Territory Enterprise Manager` не проходят из-за слов Security, NGFW или DevOps в названии. Правило одинаково для API и браузерной очереди, действует при включённом техническом fallback и не зависит от старого списка исключений в настройках. Названия вроде `Менеджер по управлению уязвимостями`, `Security Solutions Architect` и `Salesforce Developer` сами по себе не считаются продажами. Другие направления этим правилом не изменяются.

Сопроводительные письма используют ту же политику уверенной самопрезентации, что чаты и анкеты. Отсутствие инструмента или отдельного стажа по нему в профиле не вызывает перебор моделей и переход на шаблон. Инструкция ИИ не допускает выдуманные даты, работодателей, сертификаты и числовые достижения; проверки качества письма, служебных ответов сервиса, адресата и подтверждения отправки сохраняются. Если все доступные ИИ не вернули пригодного письма, бот использует шаблон и явно указывает это в журнале. Недоступные провайдеры и квоты не означают достижение лимита откликов HH.

## Выбор модели Claude

Claude CLI проверяет актуальные алиасы по возрастанию стоимости: Haiku → Sonnet → Opus. Используется первая модель, вернувшая корректный проверочный ответ; её фактическое имя и скорость сохраняются на 10 минут, затем доступ проверяется заново. Недоступная модель или тайм-аут позволяют проверить следующую, но общая квота и ошибка входа прекращают перебор Claude. Тайм-аут в меню не обозначается как квота. Для вызовов бота используется `--safe-mode`: пользовательские плагины, hooks и MCP не загружаются, вход по подписке сохраняется, настройки рабочего Claude не изменяются.

## OpenCode

OpenCode 2 подключается к общей очереди ИИ: письма, ответы на анкеты и чаты,
AI-фильтрация и анализ отказов используют его через тот же механизм проверки ответов.
Установите официальный CLI, если OpenCode ещё не установлен:

```powershell
npm install -g @opencode/cli
python hh.py settings --opencode-mode free
```

В меню **N → I → O** выбираются доступ Free / Go / Free → Go и модель из актуального каталога.
Само открытие выбора ИИ не запускает генерацию. В Free используются только бесплатные
текстовые модели; автоматического перехода на Go нет. В режиме «Авто» бесплатный
OpenCode участвует в приоритетной группе бесплатных маршрутов, закреплённый основной
провайдер сохраняет приоритет. Проверенная модель и время ответа кешируются на 10 минут.
Режим **Free → Go** ставит OpenCode первым: сначала перебираются все доступные
бесплатные модели, и только если они не ответили — модели подключённой подписки Go.
На один запрос OpenCode выделяется общий бюджет 30 секунд, включая чтение каталога,
проверки и генерацию. По его окончании отвечает следующий провайдер, даже если
каталог OpenCode ещё не исчерпан. Неопробованные модели остаются доступны для следующих запросов.
Ключ и каталог Go читаются только после исчерпания Free. Найденная модель Go не
обходит проверку Free в следующих запросах: бесплатные модели пробуются снова по
окончании их паузы или появлении новых моделей в каталоге. Включить эту очередь:

```powershell
python hh.py settings --opencode-mode auto
```

Если Free ответил, запросов к Go нет. В отдельных режимах Free и Go переход
между доступами не выполняется. По окончании цепочки работают остальные ИИ.
В Free автоматический выбор перебирает весь актуальный каталог до первого
пригодного ответа: квота модели, тайм-аут или недоступность переключают запрос
на следующую бесплатную модель. В Go автоматический выбор пропускает модели,
требующие Global regions, и ищет рабочую среди остальных; настройки Privacy
не изменяются. Отказавшая модель отдыхает 10 минут. Успешно выбранная модель
используется повторно. Если доступные модели исчерпаны, работают следующие ИИ
или существующий шаблон. Закреплённая вручную модель не переключается на другие.
В Go ошибка общей квоты или входа прекращает перебор. Ограничения времени
отдельного запроса и вызывающей задачи сохраняются; короткая проверка при запуске
может завершиться раньше полного обхода, не блокируя непроверенные модели.
Конкретную модель можно закрепить:

```powershell
python hh.py settings --opencode-mode free --opencode-model MODEL_ID
```

Для **Go** сначала подключите подписку в самом OpenCode, затем выберите Go в меню
или выполните `python hh.py settings --opencode-mode go`. Ключ подписки читается
локально и не копируется в настройки HH. Доступ к каталогу не гарантирует доступ
к генерации; действуют ограничения выбранной модели и аккаунта.

Каждый запрос использует отдельный временный профиль OpenCode, без пользовательских
плагинов и MCP. Все инструменты требуют подтверждения, которое бот не выдаёт;
запрос инструмента или частичный ответ с ошибкой не принимается. Рабочий каталог проекта и глобальные
настройки OpenCode не изменяются. Нужен OpenCode 2 с поддержкой `run --standalone`.

## Переписка с работодателями

### Правки резюме после отказов

Все найденные отказы разбираются без общего ограничения в 10 минут. Тайм-ауты отдельных
запросов к ИИ сохраняются: при сбое используются запасные провайдеры и повторный проход
по неудачным разборам. Если ни один ИИ не дал пригодного результата, отказ остаётся
отложенным с причиной, а не заменяется выдуманным анализом.

При `auto_apply_resume: true` полный цикл сводит реальные разборы в единый текст «О себе» выбранного резюме и добавляет подтверждённые профилем навыки. Новые теги не обязательны для правки текста. Если новых отказов нет, ещё не применённый план берётся из локальной базы, без открытия прочитанных чатов. Должности, прошлые работодатели, даты, стаж и зарплата не изменяются.

До записи сохраняется резервная копия в `.resume_revisions/`. После сохранения бот перечитывает редактор HH и сравнивает полный текст. Неподтверждённая правка останавливает полный цикл; повторный клик автоматически не выполняется. Фактический результат записи показывается отдельно от рекомендаций в отчётах.

После подтверждённой правки включается проверка соответствия вакансии по полному описанию и основной специализации; существующий пользовательский AI-фильтр сохраняется. Уроки отказов учитываются при отборе, но не становятся выдуманным опытом. Изменение режима действует в текущем процессе, настройки на диске не переписываются. При выключенном ИИ автоматический фильтр не включается.

Следующие отклики помечаются выбранным резюме. В следующих циклах показываются известные приглашения, отказы и ожидающие исхода отклики после правки. Старые записи без указания резюме не подмешиваются; неотвеченные отклики не считаются успехом. Автоправка не гарантирует отсутствие отказов.

Полный цикл обрабатывает только непрочитанные чаты: фильтр «Только непрочитанные» остаётся включённым, прочитанные диалоги и старые страницы отказов не открываются. После чтения карточки исчезают из очереди; бот проверяет оставшиеся непрочитанные без ограничения их числа. Если состояние фильтра не подтверждено, обход останавливается с подсказкой вместо перехода ко всем чатам. В открытой переписке бот один раз спрашивает причину отказа и отвечает на вопросы работодателя. ИИ получает инструкцию отвечать на все вопросы по пунктам; город и формат работы берутся из `candidate_profile`. На зарплатные вопросы бот отвечает без суммы. Для ответов в чатах и анкетах включена уверенная самопрезентация: ИИ отвечает утвердительно на вопросы о профессиональном опыте и может дополнять его техническими примерами, даже если инструмент не указан в резюме. Такие ответы не отклоняются из-за несовпадения со списком навыков профиля, другой нумерации или Markdown-оформления. Объём ответа задаётся инструкцией ИИ, а возможность ввода и отправки проверяется по фактическому состоянию браузера; превышение местного ориентира 3500 символов не вызывает перебор моделей. Проверки пустого ответа, служебных ошибок ИИ, адресата и подтверждения отправки сохраняются. Если ИИ не дал пригодный ответ, вопрос сохраняется для повторной обработки. Эта политика ответов не изменяет фактические данные профиля и правила анализа отказов.

`chat_autoreply.enabled` отключает отправку сообщений. `max_per_run: 0` означает отсутствие локального ограничения; положительное число ограничивает сообщения, но не просмотр чатов. `ask_rejection_reason` управляет запросами причины отказа. История `chat_actions.json` принадлежит выбранному профилю: подтверждённые сообщения не дублируются, неподтверждённая отправка требует проверки, а не автоматического повтора. Чужой черновик в поле не изменяется.

Даты в карточках чатов не используются как название компании. Если открытие диалога не подтверждено, бот один раз пытается восстановить мессенджер; перезагрузка с непустым черновиком запрещена. Два неподтверждённых чата подряд после восстановления останавливают полный цикл с конкретной причиной: правки резюме, поиск и отклики не запускаются. Непрочитанные из-за сбоя переписки сохраняются в `chat_followups.md` для повторной проверки и не считаются успешно обработанными.

При остановке терминал выводит инструкцию и варианты: `1` — открыть видимый браузер, проверить вход и загрузку чата, затем повторить проверку; `2` — открыть отчёт; `0` или Enter — завершить без откликов. Бот ждёт подтверждения перед повтором и сохраняет историю отправок. Без интерактивного терминала выводятся инструкции без ожидания ввода. Если компания найдена, но название вакансии пустое, проверяется чтение заголовка HH, а не квота ИИ. Заголовок читается из видимой карточки вакансии, в том числе когда ссылка содержит только «Перейти»; ссылки в сообщениях и списке чатов не используются для подтверждения.

Статус «в архиве» не является частью названия вакансии. Многострочный ответ вводится без клавиш Enter внутри текста: после перерисовки бот заново находит редактор, проверяет полный текст, адресата и исходный вопрос, затем отправляет один раз. Подтверждение задержалось — второе нажатие отправки не выполняется; неподтверждённая попытка остаётся в истории для ручной проверки. Старые такие попытки автоматически не повторяются.

Перекрытый или устаревший элемент отправки проверяется заново до трёх раз только при
явном отказе WebDriver до отправки. При неизвестном результате клика бот лишь проверяет
появление исходящего сообщения, не нажимая повторно. Сводка отдельно показывает ошибки
обхода, неподтверждённые отправки и действия, отложенные до отправки.

После перенаправления вакансии на вход бот проверяет сессию и открывает канонический
адрес той же вакансии. Не восстановленный вход не исключает её из будущей очереди.
На полной странице отклика резюме и письмо проверяются заново. Заголовок анкеты сам по
себе не означает наличие вопросов: допускается загруженная форма без вопросов, но
нераспознанные поля блокируют отправку. После неподтверждённой отправки допустимо только
перечитать ту же карточку без повторного клика и без перезагрузки непустого черновика.

Приглашение в ГигаРекрутер — внешнее интервью, а не реклама. `open_external_interviews: true` открывает одну ссылку на бот ГигаРекрутер в Telegram или MAX в отдельной вкладке. Авторизация и само внешнее интервью автоматически не выполняются. Неизвестные внешние ссылки не открываются. Незавершённые вопросы, неподтверждённые отправки и ссылки на интервью сохраняются в личном `chat_followups.md`; прочтение чата не означает завершение этих действий.

## TokenHarbor

Подключение: меню `N` → `J`, затем скрытый ввод вашего API-ключа `thk_...`.
Бот проверяет ключ через `https://tokenharbor.ai/v1/models`, добавляет сервис в
существующую очередь ИИ и обновляет список бесплатных текстовых моделей автоматически.
Ранее выбранный первый провайдер не меняется. Платные маршруты автоматически не включаются.
Ключ также можно задать через `TOKEN_HARBOR_API_KEY` при наличии записи сервиса в настройках.

В режиме «Авто» работающие маршруты `:free` идут перед остальными ИИ, даже если CLI
ответил быстрее. Среди бесплатных выбирается модель по измеренному времени и доле
успешных ответов; Flash/mini служат только начальным ориентиром, пока замеров нет.
Список TokenHarbor обновляется через API раз в 10 минут без ограничения на шесть моделей.
Успешное обновление удаляет исчезнувшие модели; сетевой сбой сохраняет прежний список.
Ручное закрепление провайдера сохраняет приоритет его основной доступной модели,
но не ставит весь его каталог впереди запасных сервисов. После неудачного ответа
сначала используются доступные бесплатные маршруты по скорости и успешности,
затем остальные запасные модели. Не ответившие при проверке модели уходят в конец.

Модели из Pass не являются бесплатными маршрутами: они расходуют общий лимит подписки,
а при включённом продолжении могут расходовать кошелёк. Бот не включает их по таблице
сравнения и не считает число запросов на ней замером скорости.
Условия: [Pass и списания](https://tokenharbor.ai/docs/billing/subscription).

Для бесплатных маршрутов TokenHarbor может требоваться согласие на хранение запросов
и ответов в кабинете. Бот не принимает это согласие за вас.
Подробности: [API](https://tokenharbor.ai/docs/api/curl), [приватность](https://tokenharbor.ai/faq).

## Модели Codex и Claude

При запуске бот проверяет ответ CLI-провайдеров коротким запросом без данных кандидата. Codex получает актуальный каталог через `app-server model/list` и выбирает доступную текстовую модель с наименьшей суммой официальных API-цен входа и выхода. Это ориентир экономичности, не расчёт списаний подписки ChatGPT. Если таблица цен недоступна, используются сохранённые цены или экономичное семейство Luna/mini/nano, без перехода на неизвестную дорогую модель по умолчанию.

Claude запускается с алиасом `haiku`, который следует за текущей версией Haiku. Бот сохраняет фактическое имя модели из ответа CLI. Переход Claude на Sonnet/Opus через глобальные настройки fallback отключён для запросов бота. У Codex выбирается минимальный поддерживаемый уровень рассуждений. Глобальные настройки обоих CLI не меняются.

Выбранная модель, доступность и время проверочного/последнего ответа сохраняются в `ai_stats.json`. Проверка доступа повторяется через 10 минут, каталог Codex — через 6 часов или после обновления CLI. Если выбранная модель исчезла, каталог обновляется сразу. Отказ по авторизации или квоте передаёт работу следующему ИИ, а не запускает перебор дорогих моделей. В меню и стартовом отчёте видны модель и результат проверки.

В строке «Ответ получен от … API» указываются адрес сервиса без ключей и модель из фактического ответа. Antigravity Tools может продолжать обслуживать API в фоне после закрытия окна; наличие окна не определяет доступность сервиса.

CLI должны быть установлены и авторизованы отдельно. Установка `cli_providers: []` в `ai_config` отключает их. Подписка и квоты провайдера продолжают действовать; наличие модели в каталоге само по себе не означает доступ к генерации.

## Текстовая капча

```powershell
python hh.py settings --captcha on
python hh.py settings --captcha off
```

Распознаётся текстовая картинка HH с полем ввода (`account-captcha-picture` / `account-captcha-input`). В API передаётся только снимок элемента с картинкой, без резюме и переписки. По умолчанию Vision автоматически выбирает модели для изображений у уже подключённых OpenAI-совместимых провайдеров: бесплатные первыми, затем локальные маршруты и дешёвые модели с опубликованными ценами. Каталоги обновляются раз в 10 минут, успешный маршрут и скорость запоминаются. Явно текстовые модели пропускаются. При отказе одного провайдера пробуется другой; недействительный ключ временно исключает этот сервис, а не всю обработку капчи. Старый основной API используется только запасным маршрутом. Отдельную модель можно задать через `--captcha-model` или меню N → F; `auto` возвращает автоматический подбор. Ключи не копируются между провайдерами и не выводятся в журнал.

**N → I → V** проверяет настоящий Vision API на двух случайных контрольных картинках в отдельном временном Chrome-профиле. Отклики, сообщения и правки резюме не выполняются. Это проверка распознавания, не доказательство принятия настоящей капчи HH. Общий бюджет распознавания — 45 секунд (`captcha.total_timeout_seconds`), по умолчанию не более 20 секунд на одну модель.

Отдельный провайдер настраивается в файле профиля:

```json
{
  "captcha": {
    "enabled": true,
    "provider": "openai",
    "model": "gpt-4o-mini",
    "max_attempts": 2,
    "timeout_seconds": 20
  }
}
```

Ключ можно передать через `OPENAI_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY` или поле `captcha.api_key`. Для совместимого сервера предусмотрено `captcha.base_url`.

Бот проверяет исчезновение капчи после ввода. Максимум — три попытки за обработку. При ошибке в видимом окне остаётся ручное решение. Если проверка появилась после команды отправки, Vision вызывается на исходной странице без повторного отклика. В headless после такой отправки браузер не перезапускается: если Vision не помог, отклик сохраняется как `pending_confirmation`, новые отправки останавливаются. Исчезновение капчи само по себе не считается доставкой: нужен отдельный подтверждённый статус HH. Причины отказа Vision (например, HTTP 403 или отсутствие модели/ключа) видны в журнале без ключей и текста картинки. Картинные пазлы, перетаскивание и сторонние виджеты этой функцией не решаются.

## Аккаунты

```powershell
python hh.py profiles
python hh.py --profile-id second login
python hh.py --profile-id second menu
python hh.py --profile-id second settings --ai-filter light
python hh.py --profile-id second run --headless --limit 20
```

`default` сохраняет прежние файлы в корне проекта. У остальных аккаунтов данные лежат в `profiles/<имя>/`: настройки, токены, Chrome cookies, база, история, кеши, флаги, расписание подъёма и отчёты. Существующий аккаунт в новый профиль не копируется. Имена: латинские буквы, цифры, `_`, `-`, до 64 символов.

По умолчанию отклики продолжаются до сообщения HH о лимите, окончания подходящих вакансий или остановки пользователем. Локальный счётчик не показывает полный остаток лимита HH. `--limit 20` включает отдельный пользовательский предел по локальной истории за 24 часа. В настройках поведения `0` отключает локальный предел (`stop_at_local_limit: false`); положительное число включает его. Отказ ИИ не останавливает отклики: сопроводительное письмо составляется по шаблону, а разбор отказов откладывается без записи догадок в базу.

Доставка подтверждается статусом элементов текущей вакансии, не текстом письма или фразой «ваш отклик» на странице. После финальной команды неизвестный ответ драйвера не вызывает повторную команду отправки отклика. Неподтверждённая отправка остаётся `pending_confirmation`, не учитывается как успех и не повторяется автоматически. Проверка капчи опирается на видимое поле, картинку или iframe проверки, а не на слова в описании вакансии. Если она появилась после отправки, бот сначала пробует настроенный Vision; если решить проверку или подтвердить доставку не удалось, сохраняет неподтверждённый результат. При нерешённой капче новые отправки останавливаются с подсказкой для ручной проверки. Старые записи истории автоматически не удаляются и не объявляются доставленными заново.

`HH_DATA_DIR` меняет корень данных, `HH_PROFILE_ID` выбирает профиль для прямых запусков старых Python-модулей. Для управления аккаунтами используйте `hh.py`: его команды блокируют повторный одновременный запуск того же профиля. Не запускайте старые скрипты параллельно с ним для одного аккаунта. Окна разных аккаунтов независимы.

## Расписание

```powershell
python hh.py --profile-id second schedule --headless --every-minutes 240 --limit 100
```

Первый цикл запускается сразу. Следующий — через заданный интервал после завершения предыдущего; циклы не перекрываются. Каждый цикл читает свежие настройки, обрабатывает кеш и ищет вакансии на сайте, используя существующие фильтры, дневной лимит и подъём резюме по его сроку. Ошибка цикла выводится с кодом завершения; следующий цикл пробует снова. Остановка — Ctrl+C. Для другого аккаунта запускается отдельная команда с его именем.

## Изменения 21 октября 2026

- OpenCode 2 подключён к общей очереди ИИ: доступ Free, Go или Free → Go, выбор в меню N → I → O или флагами `--opencode-mode` и `--opencode-model`.

- Текстовую капчу распознаёт Vision: модели для изображений подбираются у подключённых провайдеров, проверка — N → I → V.
- Бот запоминает ответы на анкеты как черновики; повторно подставляются только ответы, подтверждённые в меню N → Q → M.
- Доставка отклика подтверждается статусом вакансии на HH. Неподтверждённая отправка остаётся `pending_confirmation` и не повторяется автоматически.
- В чатах вопросы о зарплате, сообщения «резюме рассмотрим», просьбы перезвонить и отказ от Telegram обрабатываются без ИИ; номер телефона в чат не отправляется.
- Разбор отказов идёт без общего ограничения в 10 минут, а причиной отказа считается только цитата работодателя.
- После перенаправления на вход бот проверяет сессию и возвращается к той же вакансии, не исключая её из очереди.
- Обход непрочитанных чатов сам возвращается к списку, если открыт отдельный чат и галочки «Только непрочитанные» нет, а перед отправкой подготовленного ответа ждёт, пока откроется переписка и появится поле ввода.
- Проверка связи с hh.ru требует настоящего HTTP-ответа, а не только открытого соединения; полный цикл при недоступности ждёт до 5 минут и останавливается с понятным сообщением.
- При запуске для каждого сервиса ИИ объясняется, почему он молчит: приложение не запущено, доступ отклонён (401/403), сервис выключен в настройках или нет ключа. Срок паузы модели берётся из ответа сервиса («Cooldown wait»).
- Письма для следующих вакансий готовятся заранее (`letter_prefetch`), занятая модель пропускается, поэтому параллельные запросы расходятся по разным моделям.
- Ответы в чатах стали короче и живее: в промпт добавлены правила «живого» стиля (адаптировано из work-humanizer, MIT), примеры вашей манеры в `chat_autoreply.style_examples`, без «пожалуйста» и повторного приветствия. Номер телефона в чат не пишется никогда.
- Возражение работодателя по деньгам после нашего ответа получает встречный вопрос, а не сумму.
